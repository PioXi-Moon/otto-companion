# Otto 本体与交互模型

> 这一版要解决的问题：**语义输入不再直接映射成动作**，而是先改变它的内部状态，
> 再由状态与冲突决定行为。动作库只是出口，不是大脑。
>
> 这套东西的名字叫 **状态驱动的角色交互（State-Driven Character Interaction）**：
> 输入不产生回答，输入改变存在状态；行为不是查表，是状态的投影。

## 一、三层结构

```
用户的话 / 动作
      │
      ▼
① 言语行为层：他在"做什么"（陈述/请求/自嘲/试探…），不是"他什么情绪"
      │
      ▼
② 内部状态层：注意力 / 精力 / 安全感 / 面子 / 好奇 / 关系期待（带惯性）
      │
      ▼
③ 表达层：意图（靠近/退开/僵住/转移/沉默）→ 具体动作 + 语气 + 是否回应
```

关键：**同一个输入在不同状态下必须给出不同反应**。如果做不到，本体就是摆设。

## 二、言语行为（第一层）

不把用户的话压成"开心/难过"，而是识别他在做什么。这一层用 10 类就够跑通：

| 类型 | 例子 | 对状态的典型影响 |
|---|---|---|
| 陈述 | "今天答辩完了" | 好奇 +，注意力 + |
| 请求 | "往前走" | 注意力 +，能量 − |
| 评价 | "你挺可爱的" | 面子 +，安全感 + |
| 自嘲 | "我又搞砸了" | 安全感 −，关系期待 + |
| 试探 | "你还记得吗" | 面子 +，好奇 + |
| 示弱 | "有点难受" | 安全感 +（被信任），注意力 + |
| 拒绝 | "别烦我" | 安全感 −，面子 − |
| 玩笑 | "你是不是傻" | 好奇心 +，面子 ± |
| 关心 | "你今天怎么样" | 面子 +，安全感 + |
| 命令 | "别动" | 安全感 −，注意力 + |

识别结果带一个置信度。低于阈值时，按"没听清/不确定"处理，不强行归类。

## 三、内部状态（第二层）

六个维度，范围 0–1，都带**惯性**：涨得慢，回落也慢。

| 维度 | 基线 | 被什么推动 | 回落 | 用户能看到的差别 |
|---|---|---|---|---|
| 注意力 | 0.5 | 被叫到、被问到、新信息 + | 30 秒无输入 − | 转头/停下手上的事 |
| 精力 | 0.7 | 深夜、长对话 − | 静止时缓慢回 | 动作幅度、语速、打盹 |
| 安全感 | 0.6 | 被拒绝、被冷落 −；被信任 + | 慢回 | 靠近半步 / 退半步 |
| 面子 | 0.5 | 被夸、被戳穿 +；被贬低 − | 慢回 | 得意 / 嘴硬 / 转过脸 |
| 好奇 | 0.5 | 新信息、反常的话 + | 中等 | 探头、追问、矩阵扫描 |
| 关系期待 | 0.3 + 关系阶段 | 久未出现 +，被打断 − | 很慢 | 主动开口的频率 |

实现上存成 `{attention, energy, security, face, curiosity, attachment}`，
每次对话做一次 `update`，每个 tick 做一次 `decay`。

### 状态更新的两个原则

1. **事件的大小取决于关系阶段。** 同一个人夸它，刚认识时只加 0.1，熟了以后加 0.25。
2. **一次只动一到两个维度。** 所有维度都变，等于什么都没变。

## 四、冲突对（权重真正起作用的地方）

不是把六个维度加权求和选最高分——那是更精细的查表。先找**当前最紧的那一对拉扯**：

| 冲突 | 判定 | 三种解法（由人格决定） |
|---|---|---|
| 想靠近 × 要面子 | 安全感高、面子也高 | 直接靠近 / 嘴硬地靠近 / 转开但偷看 |
| 想继续 × 累了 | 好奇高、精力低 | 多聊两句 / 短回应 / 打盹 |
| 想被看见 × 怕被看穿 | 面子高、安全感低 | 自夸 / 害羞 / 装没事 |
| 被冒犯 × 不想撕破 | 安全感低、关系期待高 | 闹脾气 / 沉默 / 先低头 |
| 好奇 × 不想多事 | 好奇高、安全感低 | 试探 / 忍住 / 走神 |

**人格参数就是这些冲突的偏好解**，不是形容词：

| 人格档位 | 系数效果 |
|---|---|
| 傲娇 | 面子 ×1.5，安全感 ×0.8 → 冲突更容易解成"嘴硬地靠近" |
| 黏人 | 关系期待 ×1.5 → 更容易主动找你 |
| 冷淡 | 关系期待 ×0.6，安全感 ×1.2 → 更难被推动 |
| 好奇 | 好奇 ×1.5 → 更容易追问 |

## 五、表达层（第三层）

冲突解算后先得到一个**意图**，再从意图里挑动作：

| 意图 | 动作候选（现有动作库） |
|---|---|
| 靠近 | nuzzle / approach / expect / welcome_back / grateful |
| 退开 | turn_away / sulk / hide / droop / sit |
| 僵住 | confused / nervous / shake / alert |
| 转移 | tsundere / mischievous / playful / laugh / shake_head |
| 展示 | proud / excited / celebrate / dance |
| 安定 | content / relieved / listening |
| 沉默 | 不回话，只做一个很小的动作（doze / sit），或完全不动 |

### 三条让行为"像活的"的规则

1. **惯性**：上一次做过什么，这一次有加权。不会每句都换表情。
2. **扰动**：15% 概率选次优动作。人不会每次都选最优解。
3. **允许不回应**：沉默是一个显式意图，不是失败。听见了但不接、走神、装没听见，
   都是行为。

## 六、一次完整循环

```
用户说话
  → ① 识别言语行为（含置信度）
  → ② 更新六个状态（带惯性，一次只动 1–2 个）
  → ③ 找当前最紧的冲突对
  → ④ 用这个人格系数解冲突，得到意图
  → ⑤ 在意图内按权重 + 惯性 + 15% 扰动选动作
  → ⑥ 下发硬件（BLE 桥）+ 决定语气/是否回应
  → ⑦ 把"为什么这样反应"写进当天日记（可追溯）
```

第 ⑦ 步是这个模型和别人的分界线：**行为不是黑箱打分的产物，它有出处**。
用户在日记里能看到"它今天为什么这样对我"。

## 七、最小可行版本（先做这个）

| 范围 | 内容 |
|---|---|
| 状态 | 6 个维度（上表） |
| 言语行为 | 10 类 |
| 冲突 | 4 组（靠近/面子、继续/累、被看见/被看穿、被冒犯/关系） |
| 意图 | 5 种（靠近/退开/转移/安定/沉默） |
| 动作 | 10 个（nuzzle、approach、turn_away、sulk、tsundere、confused、content、excited、doze、none） |
| 调试 | 面板实时显示 6 个状态值、当前冲突、选中的意图与动作、以及加权明细 |

跑通的标准：同一句"还行"，在"刚被夸"和"刚被冷落"两种状态下，给出明显不同的反应。

## 八、现实约束

四个舵机 + 一个蜂鸣器 + 一个点阵，表达带宽很窄。所以每个维度至少要有一个
**用户一眼能看出来**的差别，否则模型再丰富，用户也感受不到。

如果某个维度暂时没有可见差别，就先不放进 MVP——宁可少一个维度，
也不要做一个只有开发者能看见的状态。

## 九、落地状态

最小版本已经写进代码：

- `server/ontology.mjs`：六维状态（带按时间回落）、10 类言语行为、5 组冲突、
  人格系数、意图 → 动作、15% 扰动与动作惯性
- `GET /api/ontology`、`POST /api/ontology/observe`、`POST /api/ontology/reset`
- 面板「测试面板 → 角色本体」：六条状态（带基线刻度）、上一次的
  「言语行为 → 冲突 → 意图 → 动作」、输入框可直接观察一句话
- 对话链路上每句用户输入都会先过一遍本体，日志里会打
  `本体：<冲突>（张力）→ <意图> → <动作>`

**意图已经成为动作的硬约束。** 对话里模型仍负责挑具体表达，但只能在本体给的意图候选里挑；
挑出圈了会被替换，并在日志里留下 `本体接管：<原动作> → <新动作>（意图 <意图>）`。

实测（2026-10-28）：

```
输入「别烦我」
本体：被冒犯 × 不想撕破（张力 0.07）→ withdraw → turn_away
实际动作：turn_away
```

### 误解与纠正

误读不是随机噪声，是**人格偏见**：冷淡型容易把短句读成敷衍；爱面子的容易把"还行"读成不想多说。
只对本来就含糊的话（陈述 / 评价）误读，明确的示弱、拒绝不会听反。

用户说"你误会了""我是说……"时，会把"这句话该怎么听"写进校准表；
下次同一句话直接走校准，不再犯同一个错。

实测：

```
1 第一次听「嗯」       → 误读成「拒绝」→ withdraw → droop
2 「你误会了，我有点累」 → 校准：拒绝 → 示弱
3 再听一次「嗯」        → 示弱 → approach → approach（calibrated）
```

### 纠正会累积到偏见本身

只记"这一句怎么听"还不够，那是查词表。同一个偏见被纠正得越多，它犯错的概率越低：

| 被纠正次数 | 误读概率 |
|---|---|
| 0 | 0.35 |
| 1 | 0.26 |
| 2 | 0.18 |
| 3 | 0.09 |

实测（冷淡型人格，固定随机数 0.1，模拟"它就是容易往敷衍那边想"）：

```
「嗯」→ 误读成拒绝 → 纠正（1 次）
「哦」→ 误读成拒绝 → 纠正（2 次）
「好」→ 误读成拒绝 → 纠正（3 次）
「行」→ 不再误读        ← 换了一句全新的话，偏见已经学会了
```

这不是"它记住了三个词"，是"它整个人不那么容易把人往坏处想了"。
