# 产品决策记录

只记那些"当时有好几个选择、最后为什么选了这个"的地方。按时间倒着排，最近的在前面。

## 1. 对话是通道，不是主界面

**选择**：把对话框从第一屏挪到"使唤它"那一页的最下面，主页换成"它今天"。

**为什么**：一个聊天框摆在第一屏，这个产品就退化成 App 了。
更关键的是逻辑对不上——打字要求你先组织出一句话，
而它要解决的恰恰是"没什么值得专门说的"那些时刻。

**代价**：第一阶段对话是唯一的记忆入口，压下去会让演示时不好展示"它记得我"。
所以证据改成由它主动给（到点主动开口、摸它的反应随关系变），而不是我问出来。
这样反而更干净：**我不想用"问它记不记得"来验证它记不记得。**

## 2. 亲密度改成"了解程度"

**选择**：把亲密度这个数值的含义换掉——不是"你喜欢我多少"，是"我了解你多少"，
无上限、只增不减，涨的来源是记住了多少关于你的事，不是聊了多少句。

**为什么**：亲密度这个词自带索取感，做久了会往"你都不来看我"那个方向滑。
了解程度是它自己的成长：记得越细，越懂你。这个方向没有尽头，也没有惩罚。

## 3. 日记要"值钱"，复述等于零分

**选择**：一页日记必须有"看见、串联、细节、悬念"里至少两样；
对话只能当证据，引一两个词就够。

**为什么**：最早那几版是把对话复述一遍。我自己读的时候没有任何等待的理由——
那些话我十分钟前刚说过。

**怎么保证**：光靠提示词不行，加了一道能算的校验，不过关就把它自己的毛病念回去重写。
（细节见 [验证报告](验证报告.md)）

## 4. 卡片只等一天，不等关系

**选择**：日记按了解程度一层层解锁；卡片只等一天。

**为什么**：卡片是它写给你的。锁着就变成"你得先亲近我才能拿到我的关心"——
正是要避开的那个味道。日记不一样，日记是它自己的东西，给不给你看是它的事。

## 5. 手账的五种版式，而不是一种排版

**选择**：一页 = 印章 + 道具 + 正文 + 页脚 + 纸面上的痕迹，
五种拼装（左图右文 / 夹一张票 / 满页 / 页边 / 一个字）。

**为什么**：一开始只有一种竖排，翻三页就腻了；而且图是贴上去的，跟文字没关系。
版式改的不是摆法，是**图文关系**：夹票那一版，票插在段落中间，读到一半会撞上它。

**约束**：连着两天不能用同一个版式，校验会拦。

## 6. 道具库，而不是让模型画图

**选择**：32 个道具，模型只挑"挑哪个 + 放哪个格子"，不自由画 SVG。

**为什么**：试过让它画，形变、越界、风格漂移全来了。
收窄成"挑"之后，它负责判断这一天该出现什么，画成什么样由代码定死。

**补的一条**：道具要挑正文里真的写到的那样东西——图和字对不上，这一页就是贴纸本。

## 7. 先决定动作，再说话

**选择**：模型读完用户那句话，第一行先写动作标签，服务端解析到就往下发；
正文跟在后头流。

**为什么**：原来写成"先在句首标一个表情"，顺序是反的——
话是照着动作说的，不是先想好一句话再补一个表情。
硬件那边也是这个道理：动作先到，反应就不会比声音慢半拍。

## 8. 硬件的提示说的是"记录"，不是参数

**选择**：面板顶部那句话写成"你在它那边说过的话、碰过它的每一次，回来都会记在这里"；
舵机角度、蜂鸣器这些挪进测试面板。

**为什么**：我第一版做成了参数条（顶上一排舵机角度），方向错了——
那是给开发者看的。用户需要知道的是：**软件是它的记忆，硬件是它的身体**，
接上之后你在真机上做的一切都会落到这里。

## 9. 一比特互动：点一下 = 摸它

**选择**：点一下是摸它（给姿态 + 一句很短的话），双击才打开面板，拖动是拎起来。

**为什么**：点它一下不该等于"打开一个 App"。
它有三条规矩：反应跟关系阶段走、八秒里连摸四下会烦、不进对话流
（摸一下不等于你说了什么，只埋点不写消息）。

## 10. 做不到的地方如实说

**选择**：断网、没配 Key、生成慢，三种情况分别有明确的表现，
不用"正在思考"糊过去，也不假装还好。

**为什么**：一个陪伴产品在能力受限的时候卖萌，比直接说"我这会儿不行"更伤人。
这条在方案里是硬底线。
