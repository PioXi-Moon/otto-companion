# Otto 硬件动作语言

Otto 没有手，头部和躯干是固定结构，没有脖子，不能做真正的“低头”或“扭头”。硬件能使用的
真实通道只有重心摆动、弹跳、坐下、跺脚、扭动、行走、四颗舵机形成的倾角，以及约 8×8 的点阵。

动作名里有 `BOW`、`TWIST`，但它们只是舵机脚位组合，不等于“低头”和“转身”。它们不再承担
这两类情绪语义。`FACE CALM/SLEEP` 是点阵图案指令；如果点阵没有接好，固件会返回 ACK，但物理上
看不到任何表情。

每个动作要明确回答三个问题：

1. **第一眼看见什么表情**
2. **身体从哪个姿态走到哪个姿态**
3. **情绪最后停在哪里**

## 一拍的结构

每个动作按三拍组合：

```text
表情标点 → 身体动作 → 停顿/回落
```

例如：

```text
傲娇：单眼 → 短促扭动 → 赌气 → 重新开心
亲近：爱心 → 摆动 → 弹一下 → 开心回落
委屈：闭眼 → 坐下 → 停住 → 恢复平静
```

动作之间不再只靠随机堆叠，而是用 `WAIT` 留出“反应时间”。没有停顿，连续指令会像机械执行；
有一次停顿，才像角色先愣住、再决定怎么回应。

## 情绪语法

| 情绪 | 表情 | 身体语法 | 收尾 |
|---|---|---|---|
| 开心 | HAPPY | 轻跳一次 + 摆身 | 回到 CALM |
| 得意 | STAR | 弹一下 + 左右展示 | 回中，不持续嚣张 |
| 好奇 | CALM / SCAN | 小幅摆身 + 扫描 | 单眼收尾 |
| 惊讶 | SURPRISE | 弹跳 + 扫描 | 单眼 |
| 亲近 | HEART | 摆动 + 弹跳 | HAPPY 后回 CALM |
| 害羞 | WINK | 坐下并缩小姿态 | HEART 一闪，再回 CALM |
| 傲娇 | WINK | 短促扭动，停住 | 重新亮起来 |
| 闹脾气 | ANGRY | 坐下并保持距离 | 最后恢复 CALM |
| 委屈 | SLEEP | 坐下 | 停住后恢复 CALM |
| 思考 | CALM | 矩阵旋转 + 坐下 | 回 CALM |
| 开心庆祝 | STAR | 跳舞 + 矩阵波浪 + 扭动 | 开心收尾 |

## 组合与语音时序

语音回答正在播放时，固件会拒绝大部分身体动作。因此完整序列按下面的时序执行：

```text
表情/短动作先进入队列
→ TTS 播放
→ VOICE IDLE
→ 主动作
→ 副动作
→ 收尾动作
```

这一步由小智服务的 TTS 生命周期触发，不由固定 sleep 猜测。

## 已知边界

- 当前固件没有蜂鸣器，`SFX` 是可选步骤，缺失时跳过，不中断后续动作。
- 点阵只有单色 8×8，表情靠眼形、嘴形和闪烁节奏区分。
- 点阵必须实际接好，否则 `FACE` 指令即使返回 ACK，用户也看不到表情。
- 舵机动作有供电峰值限制，步行使用四舵机同步插值和较低幅度。
