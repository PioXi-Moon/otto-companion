# 小智语音接入 Otto

## 当前链路

```text
小智 ESP32-S3
  │ Wi-Fi WebSocket
  ▼
电脑上的 xiaozhi-esp32-server
  │ 回答 + 动作草稿 / otto_tool
  ▼
┌──────────────────────────────────────┐
│ Otto 软件 127.0.0.1:7788              │
│ 本体校准 · 语音记录 · 音乐 · 词卡     │
│ 专注计时 · 综合状态                   │
└──────────────────────────────────────┘
  │
  ├── 面板同步动作、切歌、词卡与计时
  │
  └── 本地硬件桥 127.0.0.1:7790
        │ BLE
        ▼
      Otto Nano、点阵和舵机
```

小智负责唤醒、录音、播放；电脑负责 OTA、语音识别、DeepSeek 对话和语音合成。
Otto 本体通过本地 BLE 桥接，不再要求串口固定为 COM5。

普通语音回合会先调用 `POST /api/voice/turn`。这里不让软件重新生成一遍回答，只做两件事：

1. 用同一套六维状态和意图约束校准动作。模型可以提出动作草稿，最终演什么由本体决定。
2. 把用户原话、Otto 的回应、最终动作和物理移动写入关系记录，并异步抽取长期记忆。

如果 Otto 软件没启动，语音控制仍会回退到原来的硬件桥直连；这时能说、能动，但这一轮不会
进入长期关系记录。这个降级是有意的，不能因为记忆服务掉线就让硬件整体不可用。

## 能用嘴开的功能

语音工具和面板按钮共用 `POST /api/tools/run`，所以不会出现“小智说播放了，面板却没变”的
两套状态。当前支持：

| 用户说法 | 实际动作 |
|---|---|
| 来首歌 / 放首歌 / 播放中秋月 / 播放一念千年 | 实体小智直接播放服务器 `music/` 里的歌曲 |
| 放一首雨天的歌 / 放电脑端环境音乐 | 电脑端 Otto 面板播放实时合成音乐 |
| 暂停电脑端音乐 / 继续放 / 电脑端声音小一点 | 暂停、继续、调整面板音乐音量 |
| 背单词 / 换校园词汇 / 下一个 / 再来一遍 | 打开词卡并切换主题、当前词 |
| 这个词记住了 / 还不熟 | 写入单词学习进度 |
| 考我一个词 / 答案是…… | 出中文选择题并判定结果 |
| 来个二十五分钟番茄钟 / 深度工作五十分钟 | 启动对应专注模块 |
| 现在在做什么 | 汇总音乐、词卡和专注状态 |
| 打开音乐 / 打开词卡 | 打开面板并切到对应页面 |

## 启动

1. 启动 Otto 桌宠。
2. 双击 `启动小智服务端.bat`。
3. 第一次启动需要约 60～90 秒加载本地语音模型，日志出现下面两行后再使用小智：

```text
OTA接口是        http://电脑局域网IP:8003/xiaozhi/ota/
Websocket地址是   ws://电脑局域网IP:8000/xiaozhi/v1/
```

本次启动时电脑地址为 `10.196.19.108`，对应地址：

```text
OTA:       http://10.196.19.108:8003/xiaozhi/ota/
WebSocket: ws://10.196.19.108:8000/xiaozhi/v1/
```

电脑 IP 改变后，只需重新查看启动日志；OTA 和 WebSocket 地址会自动使用当前局域网 IP。

## 配置小智

1. 进入小智的配网页面。
2. 打开“高级选项”。
3. OTA 地址按本次启动日志填写。当前是：

```text
http://10.196.19.108:8003/xiaozhi/ota/
```

4. 保存并重启小智。
5. 电脑上的小智服务日志应出现来自设备 IP 的 WebSocket 连接和 `hello` 消息。
6. 唤醒小智并说：“让 Otto 开心一下”。
7. 再说：“播放中秋月”，确认音乐从实体小智播放。
8. 再说：“背几个单词”，确认电脑端 Otto 面板同步切到词卡。

## 自动选择动作

小智不是按关键词查表。`otto_react` 会把整段对话的情绪、关系、语境和回答意图交给
DeepSeek 判断，再由 DeepSeek 从现有动作库中选择最多一个最贴切的动作。

例如：

- “今天答辩终于过了，不过我不想表现得太得意” → `proud`
- “算了，说了你也不懂” → `droop`
- “你猜我发现什么了” → `lean_in`
- “帮我记住明天三点交材料” → `confirm`

目前可选 43 个动作：

- 中性 / 情绪：平静、开心、好奇、惊讶、困倦、委屈、生气、得意、害羞、心虚、闹脾气、失落、记挂、期待、紧张
- 社交 / 陪伴：挥手、欢迎、偷看、庆祝、坐着陪、靠近、躲一下、欢迎回来、撒娇、嘴硬、回避、瘫倒
- 对话反馈：思考、倾听、学习、完成、困惑、等待确认
- 安静 / 状态：伸懒腰、自己玩、打盹、熄屏
- 移动：前进、后退、左转、右转、原地弹跳、扭动

用户明确要求控制时还支持：归中、停止、安静模式、恢复正常模式。

移动动作与其他动作一起常驻动作库，不会因为实体暂时未连接而从列表中消失。
未连接时只会在执行阶段返回硬件离线；重新连接后立即恢复使用。

“说话”不是可选语义动作，而是由 TTS 实际播放状态固定控制：第一段语音发送前切到
`VOICE SPEAKING`，点阵嘴部按固件节奏开合；最后一段语音播放完成或被用户打断后切回
`VOICE IDLE`。

`Otto` 软件没启动时，`otto_tool` 会明确说“桌面端 Otto 没在运行”；硬件动作仍可继续由
`otto_react` 和硬件桥处理，不会把所有语音功能一起拖死。

## 流畅度优化

- 动作选择和正文回答由同一次模型调用完成，Otto 知道自己的动作能力，也不需要额外串行往返。
- 系统提示词从约 6200 字缩减到约 380 字，减少模型首字等待。
- TTS 第一段不再按逗号切开，避免零点几秒短音后出现空档。
- VAD 静音判断从 350ms 放宽到 600ms，减少话没说完就被截断的情况。

## 文件

- 启动入口：`启动小智服务端.bat`
- 启动脚本：`scripts/start-xiaozhi.ps1`
- 服务端：`vendor/xiaozhi-server/main/xiaozhi-server`
- 本地配置：`vendor/xiaozhi-server/main/xiaozhi-server/data/.config.yaml`
- Otto 工具：`vendor/xiaozhi-server/main/xiaozhi-server/plugins_func/functions/otto_control.py`
- 软件工具：`vendor/xiaozhi-server/main/xiaozhi-server/plugins_func/functions/otto_tool.py`
- 语音模型：`vendor/xiaozhi-server/main/xiaozhi-server/models/SenseVoiceSmall`

## 排查

**小智显示找不到服务器**

- 确认电脑和小智在同一 Wi-Fi。
- 在电脑浏览器打开 OTA 地址，应显示“OTA接口运行正常”。
- 确认 Windows 当前网络为“专用网络”。
- 防火墙需允许 TCP `8000` 和 `8003` 入站。

**小智能对话，但不能控制 Otto**

- 动作问题：确认 `http://127.0.0.1:7790/health` 返回 `ok`，且 BLE 名称 `OTTO` 已连接。
- 软件功能问题：确认 `http://127.0.0.1:7788/api/modules` 能打开。
- 语音工具日志应出现 `Otto 工具 word_start...`、`Otto 工具 music_play...` 等记录。
- 实体小智自己的音乐放在 `vendor/xiaozhi-server/main/xiaozhi-server/music/`，
  支持 `.mp3`、`.wav` 和 `.p3`。新增歌曲后重启小智服务端即可。
- 修改 `.config.yaml` 或 `otto_tool.py` 后必须重启小智服务端。

**第一次启动很慢**

这是 SenseVoiceSmall 本地语音模型在加载。等出现 OTA 和 WebSocket 地址后再使用。

**电脑 IP 改变**

- 重新设置小智的 OTA 地址。
- 或尽量给电脑设置 DHCP 地址保留。
